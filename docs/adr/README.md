# 설계 판단 기록 (ADR)

이 프로젝트에서 내린 설계 결정과 그 이유를 남긴다. 한 문서는 결정 하나를 다룬다.

각 문서의 구성:

- **문제**: 무엇이 문제였는가
- **검토한 대안**: 어떤 선택지가 있었는가
- **결정**: 무엇을 골랐는가
- **이유**: 왜 그것을 골랐는가
- **결과**: 얻은 것과 감수한 것
- **근거**: 코드 위치, 테스트, 측정값
- **한 줄 설명**: 면접에서 말할 요약

"제안"은 설계만 확정하고 구현과 측정이 남은 것이다. 구현 뒤 측정값을 채우고 "결정됨"으로 바꾼다.

- 0014는 0005의 촬영 시점, 0004의 종료 규칙 입력, 0010의 방법 2 시기를 바꾼다. 서버가 판단한다는 원칙과 2회 연속 확정은 그대로다.
- 0015는 0011을 대체했고, **0017이 다시 0015를 대체한다**(OCR 제거). 어긋나 보이면 0017을 따른다. 0015의 측정값은 역사 기록이다.
- 0016은 AWS 구축의 사전 작업이다. 당시 "Phase 1" 이라 부른 구조(Flask + YOLO 한 Pod 를 EKS 에)는 2026-10-30 부터 **Prototype** 이라 부른다. 새 Phase 1 은 0018, Phase 2 는 0019 다. 전체 흐름은 `docs/design/ARCHITECTURE_EVOLUTION.md`.
- 인프라 쪽 결정도 이 번호 체계에서 다음 번호를 쓴다(2026-10-30 변경. 이전에는 infra 레포 `docs/adr/` 에 0018부터 두기로 했으나 그 파일은 만들어진 적이 없다).
- 0014와 0015의 설계 원문은 저장소 루트 `AI_FINAL_DESIGN.md` 다. 그 이전 초안 `AI_SYSTEM_DESIGN.md` 는 대체됐다.

새 결정을 추가할 때는 다음 번호로 파일을 만들고 이 표에 한 줄을 더한다. 이미 내린 결정을 바꿀 때는 기존 문서를 고치지 않고 새 문서를 만들어 이전 문서를 대체한다고 적는다.
