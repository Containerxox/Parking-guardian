# 0004. 주차 한 번을 위반 한 건으로 묶는다

- 상태: 결정됨 (2026-10-02)

## 문제

장비는 1분마다 사진을 찍어 서버로 보낸다. 처음 구현은 사진 한 장을 사건 하나로 취급했다. 스티커 없는 차가 2시간 주차하면 위반 120건, 사진 120장, 담당 관리자마다 알림 120개가 생긴다. 이 상태로는 실제 장비를 붙일 수 없다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| 번호판 OCR로 같은 차량인지 구분한다 | 같은 번호판도 사진마다 다르게 읽히고, 못 읽는 사진이 반드시 생긴다. OCR을 넣어도 시간 기준 규칙이 결국 필요하다 (0011 참고) |
| 일정 시간 안의 위반은 무시한다 | 차가 나갔다가 다른 차가 들어온 경우와 구분하지 못한다 |
| 같은 장비의 연속 판정을 하나의 사건으로 묶는다 | 채택. 모델 추가 없이 해결된다 |

## 결정

경비원이 1분마다 자리를 한 번씩 쳐다보는 것처럼 동작하게 한다. 장비 한 대가 주차면 하나를 본다고 가정한다.

| 규칙 | 내용 | 설정값 |
|---|---|---|
| 1 | 위반 판정이 2번 연속이면 사건을 만들고 알림을 1번 보낸다. 1번은 기억만 한다 | `VIOLATION_CONFIRM_COUNT=2` |
| 2 | 사건이 진행 중이면 새로 만들지 않고 마지막 확인 시각과 탐지 횟수만 고친다 | |
| 3 | 차량 없음이나 정상 판정이 3번 연속이면 사건을 종료한다 | `VEHICLE_CLEAR_COUNT=3` |
| 4 | 사진이 10분 넘게 끊기면 진행 중인 사건을 닫고 다시 센다 | `EPISODE_GAP_MINUTES=10` |

**"진행 중"의 기준은 처리 상태가 아니라 차량이 아직 있는가다.** 관리자가 처리 완료를 눌러도 차가 그대로 있으면 사건은 진행 중이다. 그래야 신고를 마친 차량에 대해 다음 사진부터 알림이 다시 가지 않는다.

종료 사유는 세 가지로 구분한다: 차량 이탈, 같은 자리에서 스티커 탐지(처음 판정이 틀렸을 가능성), 신호 끊김.

## 이유

- 2번 연속으로 확정: 사진 한 장의 오판과 잠깐 정차한 차량을 걸러 낸다. 대신 알림이 1분 늦어진다.
- 3번 연속으로 종료: 사람이 카메라 앞을 지나가거나 사진 한 장이 흐려도 차가 나갔다고 잘못 판단하지 않는다.
- 횟수 상태를 메모리가 아니라 DB(장비 row)에 둔다: 서버가 재시작되거나 여러 대로 늘어도 판정이 이어진다.

## 중복 방지는 DB가 보장한다

같은 사진이 재전송되거나 두 요청이 동시에 들어올 수 있다. 장비 하나에 종료되지 않은 사건은 하나만 있도록 조건부 UNIQUE Index를 둔다.

```sql
CREATE UNIQUE INDEX uq_violations_active_per_machine
ON violations (machine_id) WHERE ended_at IS NULL;
```

애플리케이션은 장비 row를 잠그고 처리하지만, 그 잠금이 뚫려도 DB가 두 번째 사건을 거부한다.

## 결과

- 얻은 것: 2시간 주차에 위반 1건, 알림 1번. 오탐 한 장으로 알림이 가지 않는다.
- 감수한 것: 위반 차량이 나가고 3분 안에 다른 위반 차량이 들어오면 같은 사건으로 이어진다. 차량을 구분할 수단이 없기 때문이다.
- 차량이 나가도 자동으로 처리 완료하지 않는다. 조치 기록은 사람이 남긴다.

## 근거

- 규칙: `backend/app/services/detections.py`
- 테스트: `backend/tests/test_episodes.py` 8개. 120번 연속 업로드에 위반 1건과 알림 1번, 처리 완료 후에도 새 사건 없음, 이탈 후 재탐지는 새 사건, 장비별 독립, DB 제약
- PostgreSQL에서 같은 장비로 동시에 4건을 보내 위반 1건만 생기는 것을 확인했다

## 한 줄 설명

1분마다 들어오는 사진을 "주차 한 번 = 위반 한 건"으로 묶어, 2회 연속으로 확정하고 3회 연속 미탐지로 종료하며, 중복은 조건부 UNIQUE Index로 DB가 막도록 했습니다.
